# 微信知识工作区

入口：聊天窗口的书本按钮，或菜单栏 → **微信知识库与备份**。

## 我的知识库

第一版专门收集你发到微信文件传输助手的内容：原文、HTTP(S) 链接和附件。
在连接设置中选择微信 `db_storage` 目录及已有的私有密钥文件，再点击保存并同步。
默认使用 Tars 内置的 GreenBubbles 工具，无需单独安装 CLI，也不需要 flomo 会员或 AI 账号。

每次同步最多读取 20 页、每页 100 条。未完成的历史记录会保存进度；继续同步可续传。
应用打开工作区后，开启自动同步会每 30 秒检查一次。关闭工作区窗口仍保留同步状态；退出 Tars 后停止。
搜索、分类、原文查看、复制、附件打开均在本机执行，不调用模型。

默认保存到 `~/Library/Application Support/TarsKnowledge`，也可选择其他目录：

- `knowledge.sqlite`：本地搜索索引及账号各自的同步进度。
- `entries/<消息哈希>/note.md`：Markdown 正文。
- `entries/<消息哈希>/source.json`：完整的 CLI 消息来源及解码状态。
- 同目录的附件：已经下载且成功解码的独立副本，保存前检查字节数及 SHA-256。

目录权限 0700、文件 0600；知识库正文是本地明文，微信数据库密钥不会写进知识库。
未下载、过期、当前 Mac 缺失或无法解码的附件会显示状态，原消息仍保存。
在微信下载附件后可重试；一次重试最多 100 个，后续批次会继续处理其他未保存附件。
微信端未同步到本机或超出 CLI 解码上限的内容，无法凭空补齐。

首次密钥配置遵循内置 GreenBubbles 文档。Tars 不自动重新签名微信、不自动执行 sudo 或发送微信消息。

## 聊天与备份

复用原项目的原生历史浏览器：只读查询微信、聊天分页、搜索、来源覆盖率、
导出记录及联系人查看、媒体访问、加密快照创建和多种快照解锁方式。
查询兼容 GreenBubbles 0.10.0 的原始 JSON 输出。

## AI 笔记与完整工具箱

内置全部官方 0.10.0 工具、技能、脚本、文档及许可证。
界面提供聊天、附件、备份、个人记忆、AI 上下文、账号配置、导出、恢复、副本、审计、
公众号文章、账号发现及密钥工具的操作入口；高级功能在工具终端执行原项目命令。
公开发行版的消息发送限制沿用原项目，不能实际发送。

“在 Tars 中整理文件传输助手”会准备最近 30 天的整理任务，使用当前知识库连接和内置技能，
由用户点击发送后交给当前 Tars 模型。读取到的消息届时会进入所选 AI 服务，
生成的带引用笔记保存在知识库的 `ai-notes/`。已有输入草稿不会被覆盖。
所有 Tars agent 驱动的子进程都能在 PATH 中找到内置的 GreenBubbles 工具。

## 构建与验证

运行 `./build.sh`。Swift UI 依赖锁定到 fork 的提交；完整 CLI 固定为官方 0.10.0 Apple Silicon 发行版，
打包前校验下载 SHA-256 和每个可执行文件的签名。下载缓存位于 `.greenbubbles-cache/`。
Tars 主程序仍为 arm64 + x86_64；微信工具目前只支持 Apple Silicon。

可在独立示例会话中检查界面：

```sh
open -n Tars.app --args --wechat-preview --demo --library /tmp/tars-wechat-demo
```

该模式使用合成示例，不查询真实微信、不启动 AI 引擎。
